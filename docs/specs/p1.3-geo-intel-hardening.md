## 1. Mission

Make the Claude `web_search` live path production-grade: per-region TTL caching, request
timeout + bounded retries, robust JSON extraction that tolerates real-model formatting,
reliable citation collection, and correct handling of tool-use stop reasons — while keeping
the keyless mock path and the degrade-to-mock-on-error behavior exactly as they are.

## 2. Context — what exists today

All in `src/lib/providers/geoIntel.ts`:

- `getGeoIntel(region)` (`:12-24`): trims region, defaults to `"Iran and nearby airspace"`,
  `hasClaude()` gate, try `liveIntel` / catch → mock with the failure prefixed into
  `summary`. **Keep this orchestration shape.**
- `liveIntel` (`:26-75`): creates a **new `Anthropic` client per call** with no `timeout`
  or `maxRetries`; one `messages.create` with
  `tools: [{ type: "web_search_20250305", name: "web_search", max_uses: 5 }] as any`,
  `max_tokens: 1500`. No cache — every UI click is a fresh billable web-search call.
- Prompt (`:30-37`) asks for a trailing JSON object of shape
  `{"heat","headline","summary","airspaceNotes","airlineCancellations"}`.
- `extractJson` (`:77-88`) takes `text.lastIndexOf("{")`…`lastIndexOf("}")` — **broken when
  the final JSON contains nested objects** (the last `{` is then an inner brace and the
  parse fails silently → empty object → generic "Risk assessment" headline). This is the
  main robustness bug.
- Citation collection (`:50-61`) reads `block.citations` off text blocks and items from
  `web_search_tool_result` blocks. The `web_search_tool_result` content items are search
  *results* (every hit, not only cited ones) — they pollute `sources`. Citations on text
  blocks are the real signal.
- `normalizeHeat`, `toStrArray`, `dedupeSources`, `mockIntel` (`:90-136`) are fine — keep.
- The Anthropic model comes from `ANTHROPIC_MODEL` (default `claude-sonnet-4-6`,
  `src/lib/config.ts:8`). SDK: `@anthropic-ai/sdk@^0.100.1` (package.json).
- The API route `src/app/api/geo-intel/route.ts` sets `maxDuration = 60` — your client-side
  timeout must fit inside that.

## 3. Non-goals

- No streaming, no UI changes, no prompt-engineering beyond what's specified below.
- No persistent cache (in-memory `Map` is correct here; P2.2 may move it to the shared
  cache utility — keep the cache logic in small, extractable functions).
- Do not switch to forced tool-use/structured outputs in this task — the trailing-JSON
  contract is kept, just made robust. (Rationale: server web-search tool + forced JSON
  response format interact awkwardly; out of scope to re-architect.)

## 4. Design decisions (pre-made)

1. **Cache**: module-level `Map<string, { at: number; value: GeoIntel }>` keyed by
   `region.trim().toLowerCase()`. TTL from `GEO_INTEL_CACHE_TTL_MIN` (default 15 min).
   Cache **only successful live results** — never cache the error-degraded mock, so a
   transient failure doesn't pin mock data for 15 minutes. Serve-stale-on-error: if a live
   call fails and an **expired** cache entry exists, return it with a `summary` prefix
   `"(Refresh failed; showing cached assessment from <ISO time>.)"` — better than mock.
2. **Client construction**: `new Anthropic({ apiKey, timeout: 25_000, maxRetries: 1 })`.
   The SDK retries 429/5xx/connection errors itself, and attempts run **sequentially** —
   budget arithmetic: worst case ≈ 25s + backoff (~1s) + 25s ≈ 51s, inside the route's
   60s `maxDuration` with margin. Additionally, `liveIntel` tracks wall-clock from its
   start and **skips pause_turn continuation rounds once ~35s have elapsed** (each
   continuation is its own timed request — without this guard the platform kills the
   function before our graceful mock fallback can win). Never raise these numbers
   without redoing this arithmetic.
3. **`pause_turn` handling**: long server-tool turns can return `stop_reason: "pause_turn"`.
   Handle by looping: if `resp.stop_reason === "pause_turn"`, append the assistant content
   as a message and call `messages.create` again with the same tools, max **2** continuation
   rounds, accumulating content blocks from every round.
4. **Robust JSON extraction** (replaces `extractJson`): scan from the **end** of the text
   for each `{` candidate (rightmost first), attempt `JSON.parse` on a **brace-balanced**
   slice (count `{`/`}` while respecting strings), return the first parse that succeeds
   **and** contains a recognized key (`heat`/`headline`/`summary`). Also strip Markdown
   code fences (` ```json … ``` `) before scanning. Return `{}` if nothing parses (existing
   fallback behavior at `:68` then uses raw text — keep that).
5. **Prompt tightening** (keep the same data contract, reduce parse failures): instruct
   “Output the JSON as the very last line, with no code fences, no trailing commentary.”
   and “If you cannot determine a field, use an empty string/array — never omit keys.”
6. **Citations**: collect from `block.citations` (type `web_search_result_location`:
   fields `url`, `title`, `cited_text`) as the primary source list. Only fall back to
   `web_search_tool_result` items when **zero** citations were found. Keep `dedupeSources`
   + `.slice(0, 8)`.
7. **Tool typing**: try removing the `as any` by using the SDK's
   `Anthropic.Messages.WebSearchTool20250305` type / `tool` union from `@anthropic-ai/sdk`
   v0.100+. If the installed SDK genuinely lacks the type, keep `as any` with a one-line
   comment naming the SDK version checked.

## 8. Edge cases & failure modes

- **Model returns no JSON at all** → `extractJson` yields `{}` → existing fallbacks fill
  fields from raw text (`:66-70`). Keep that path working.
- **`max_uses` exhausted mid-thought** → response is still a normal end_turn with whatever
  it found; no special handling.
- **Region strings that differ only by case/whitespace** must share a cache entry (the
  normalized key handles this).
- **Clock-skew-free TTL**: use `Date.now()` deltas only (as `flights.ts` does).
- **Unbounded cache growth**: regions are user-typed; cap the Map at ~100 entries
  (evict oldest on insert — a 5-line LRU is enough).
