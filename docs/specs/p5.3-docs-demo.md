## 4. Design decisions (pre-made)

1. **README is the front door, DEMO.md is the script.** README gets: hero screenshot,
   feature list (current), quick start, config table (generated from `.env.example`),
   hosting (login-gate flow + Vercel), operations (health endpoint, logs, Sentry opt-in —
   from P4.3), project layout, roadmap/specs links, disclaimer. DEMO.md gets the
   timed, step-by-step walkthrough with expected outputs.
2. **Demo is keyless-first** (shadow mode is the product's signature): the core script
   requires zero keys and zero accounts; an appendix shows the "now add keys" upgrade
   moment (the badges flipping `mock` → `live`).
3. **Canonical demo route: London → New Delhi** (already the form default —
   `page.tsx:34-35` — and it crosses the Iran FIR, lighting up every feature: crossing
   warning, reroute, flagged itineraries, regional intel).
4. **Asset set** (in `docs/assets/`, PNG + one GIF, ≤ 300 KB each — resize to ~1400px):
   `hero.png` (full app, route planned), `map-reroute.png` (P5.2's polished map with
   legend + popup), `intel-card.png`, `mobile-360.png` (P5.1's layout), `demo.gif`
   (plan→results, ~15s). Capture at 2x, then downscale. GIF via `ffmpeg` from a screen
   recording, or a scripted Playwright capture if available — agent's choice; document
   the method in DEMO.md so it's repeatable.
5. **DEMO.md structure**: prerequisites (node ≥22) → `npm install && npm run dev` →
   walkthrough table (step | action | expected result — with the *exact* expected badge
   text `mock`/`live`, the warning strings, and the reroute "+N km" line) → status-check
   demo (use a deterministic mock example: flight `EK7`, any date — note output is
   deterministic per (flight,date)) → "go live" appendix (which key unlocks what, linking
   the config table) → troubleshooting (port busy, Nominatim miss, geo-intel slow).
6. **Cross-doc hygiene**: ROADMAP gets all boxes ticked + a top banner line "✅ Shipped —
   see docs/specs/ for the execution record"; every spec in `docs/specs/` whose task
   merged gets Status `done` (sweep them); README's roadmap link text updates from
   "ship-it-for-real plan" to "execution record".

## 8. Edge cases & failure modes

- **Mock data nondeterminism in screenshots**: mock flights derive times from `Date.now()`
  (`flights.ts:186-218`) — screenshots will show different times than a reader sees;
  fine, but DEMO.md expected-results must describe *shapes* ("4 itineraries, first
  nonstop, prices ~$400–700"), not exact values, except where deterministic
  (status for a fixed flight+date *is* deterministic — but only per-date; phrase as
  "consistent across repeated checks for the same date").
- **Private-repo clone in DEMO prerequisites**: the reader needs repo access + SSH —
  state it; don't paper over it.
- **GIF bloat**: 15s at full res blows the budget — 10–12 fps, 1000px wide, palette-
  optimized (`ffmpeg -vf "fps=11,scale=1000:-1:flags=lanczos,split[s0][s1];[s0]palettegen[p];[s1][p]paletteuse"`).
- **Live-URL screenshots vs localhost**: prefer localhost (no auth gate in shots, no URL
  leakage of the deployment); mention the live URL only in prose if the user wants it
  public at all — **ask before printing the production URL in the README** (private repo
  today, but READMEs outlive privacy settings).
