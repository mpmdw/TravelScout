## 1. Mission

Grow the existing build-only workflow into a full quality gate — **lint, typecheck, test,
build, secret-hygiene check** — required on every PR, with deployment on merge to `main`
handled by the Vercel Git integration (or, if explicitly needed, by an Actions deploy job).

## 2. Context — what exists today

- `.github/workflows/ci.yml`: single `build` job — checkout, Node 22 + npm cache,
  `npm ci`, `npm run build`. Header comment reserves lint+tests for P2.4/this task;
  P2.4 adds `npm test` when it lands. Concurrency-cancel and `contents: read` permissions
  are already correct — keep them.
- **ESLint is not actually set up**: `package.json` has `"lint": "next lint"` but there is
  **no eslint config file and no eslint devDependencies** — running `next lint` today
  starts an *interactive* setup wizard, which would hang CI. This task makes lint real and
  non-interactive.
- No `typecheck` script; `next build` type-checks, but a separate fast
  `tsc --noEmit` step gives clearer failure attribution.
- P3.2 added `scripts/check-client-secrets.sh` (greps `.next/static` for secret env names
  post-build) — designed for CI adoption here.
- Deploys: P4.1 connected the repo to Vercel's Git integration → production deploy on push
  to `main`, preview per PR. **Deployment automation already exists** by the time this
  task runs.
- Repo constraint: `gh` CLI is **not authenticated** — anything requiring GitHub settings
  (branch protection, repo secrets) is dashboard work → mark HUMAN.

## 3. Non-goals

- No release tagging/changelogs, no matrix builds (one Node version — 22 — matches CI today).
- No coverage upload services.
- No CodeQL/dependabot config (worthwhile, but not this roadmap item — mention as
  follow-up in the PR if desired).

## 4. Design decisions (pre-made)

1. **Deploy strategy — Alternative A (default): Vercel Git integration deploys; Actions
   only gates.** Rationale: the integration already does prod+preview deploys with zero
   secrets in GitHub; duplicating deploys in Actions adds two systems for one job. The
   roadmap's "merges to `main` deploy" is satisfied by the integration.
   **Alternative B (only if the user asks for Actions-owned deploys)**: disable the
   integration's auto-deploy, add a `deploy` job using `vercel build` + `vercel deploy
   --prebuilt --prod` with `VERCEL_TOKEN`/`VERCEL_ORG_ID`/`VERCEL_PROJECT_ID` repo secrets
   [HUMAN: create token + secrets in dashboards]. Do not implement B speculatively.
2. **ESLint**: classic config `.eslintrc.json` with `{ "extends": "next/core-web-vitals" }`
   plus devDeps `eslint@^8` + `eslint-config-next@^15` (the combination `next lint`
   expects for Next 15 — verify against the installed Next version's docs; if the repo's
   Next has moved to ESLint 9 flat-config support, prefer that and note it). Fix or
   `eslint-disable` (with justification) anything it flags — expect a handful of findings
   (`no-explicit-any` is *off* in core-web-vitals; the `eslint-disable` comments already
   present in providers were written for it and are harmless).
3. **Scripts**: add `"typecheck": "tsc --noEmit"`. Keep `lint` as `next lint` (Next wires
   the config dirs).
4. **One job, ordered steps** (lint → typecheck → test → build → secret-check) rather than
   parallel jobs: total runtime is ~2-3 min; parallel jobs would re-`npm ci` for marginal
   gain. Revisit if the suite slows.
5. **Branch protection** [HUMAN]: require the `Build & type-check` (rename to `Quality
   gate`) check on `main` via GitHub settings. Documented as a step, not scripted (no gh
   auth).

## 5. Execution plan

**Step 0 — preflight.** P2.4 merged (`npm test` exists and is green); branch.

**Step 1 — make lint real.** `npm i -D eslint eslint-config-next`; add `.eslintrc.json`;
run `npm run lint`; fix findings (commit lint fixes separately from workflow changes for
reviewability). Verify non-interactive: `CI=1 npm run lint` completes without prompts.

**Step 2 — typecheck script** per decision 3; run it.

**Step 3 — workflow.** Update `ci.yml`:
```yaml
jobs:
  quality:
    name: Quality gate
    runs-on: ubuntu-latest
    env: { NEXT_TELEMETRY_DISABLED: "1" }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "22", cache: npm }
      - run: npm ci
      - run: npm run lint
      - run: npm run typecheck
      - run: npm test
      - run: npm run build
      - run: ./scripts/check-client-secrets.sh   # if P3.2 has landed; it rebuilds — see note
```
Note: `check-client-secrets.sh` as written by P3.2 runs its own `npm run build`; to avoid
a double build, change the script to accept `SKIP_BUILD=1` (guard the build line) and call
it with `SKIP_BUILD=1` after the build step — coordinate the tiny script edit here.
Update the workflow's header comment (it currently promises lint/tests "as part of
roadmap P2.4" — now delivered).

**Step 4 — prove it.** Push the branch, open the PR, and confirm: all steps run; the
Vercel bot posts a preview URL (integration from P4.1); a deliberate lint error on a
scratch commit fails the run (then drop the commit).

**Step 5 — [HUMAN] branch protection** per decision 5. Document in README (a one-liner in
the contributing/deploy section).

**Step 6 — roadmap.** Tick P4.2; note in the PR that deploy-on-merge is fulfilled by the
Vercel Git integration (decision 1).

## 8. Edge cases & failure modes

- **`next lint` deprecation drift**: Next has been migrating toward standalone ESLint
  invocation; if `next lint` warns of deprecation on the installed version, switch the
  script to `eslint .` with the flat config — decide by what the installed version
  documents, not by this spec.
- **ESLint findings in generated/legacy code**: don't mass-disable rules; per-line
  disables with reasons only. If a rule fights the codebase (e.g. unescaped quotes in
  JSX copy), prefer fixing the copy (`&apos;` is already used in `page.tsx:257`).
- **npm cache poisoning across Node versions**: pinned to 22 — if you bump Node, bump it
  here and in `package.json#engines` (add engines while you're in there: `"node": ">=22"`).
- **Vercel deploys racing CI**: previews deploy regardless of CI status — that's by
  design (preview ≠ merge). Branch protection guards `main`.
