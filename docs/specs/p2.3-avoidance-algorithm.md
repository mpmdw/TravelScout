## 1. Mission

Replace the single-waypoint north/south heuristic with a **visibility-graph + shortest-path
detour** that routes around **all** configured zones simultaneously, returns a path that
provably clears every `avoid` zone, handles the antimeridian and high latitudes, and keeps
added distance reasonable — with regression tests proving each property.

## 2. Context — what exists today

All in `src/lib/geo.ts` (147 lines):

- `planRoute(origin, destination, zones)` (`:57-103`) — public API. Builds the direct
  great-circle, finds `intersectedZones`, then calls `computeAvoidance` **only with the
  intersected zones' features**. Returns `RouteResult` (`types.ts:33-44`) where
  `avoidancePath: [lng,lat][] | null`. **The signature and return shape must not change**
  — both flight providers and `/api/route` call it, and `MapView` draws the coords.
- `computeAvoidance` (`:110-146`) — the heuristic being replaced: bbox of intersected
  zones, single waypoint at `(maxLat+margin, midLng)` or `(minLat−margin, midLng)`,
  margins 2..14 step 2, first margin that clears wins, shorter of north/south. Known
  failure modes:
  - a detour that clears the *intersected* zones may newly cross a **different** configured
    zone (only intersected features are checked — `planRoute:91-94` passes just those);
  - one waypoint can't thread between/around concave or multiple zones;
  - `midLng = (from.lng + to.lng)/2` is wrong across the antimeridian (e.g. Tokyo→LA gives
    midLng ≈ 0 — the Atlantic);
  - margins are degrees latitude — near poles this distorts heavily.
- Helpers to reuse as-is: `greatCircleCoords` (`:19-39`, returns `[lng,lat][]`, flattens
  turf MultiLineString — note this flattening **already mangles antimeridian-crossing
  lines** by stitching segments at ±180 into one array; see decision 5),
  `lengthKm` (`:41-44`), `pathIntersectsZone` (`:46-49`), `closeRing`/`zonePolygon` (`:7-16`).
- Dependencies available: full `@turf/turf` v7 (buffer, bbox, booleanIntersects,
  booleanPointInPolygon, simplify, greatCircle, etc.).
- Tests: P2.4 created `tests/avoidance.test.ts` with the current behavior pinned; this task
  extends it (see §6) and may rewrite cases that pinned heuristic-specific outputs.

## 3. Non-goals

- No altitude/airways realism, no wind, no per-airline preferences — geometric avoidance only.
- No UI changes (the green polyline just gets more interesting shapes).
- `caution`-severity zones: still treated like `avoid` for detection; **do not** start
  treating them differently in this task (currently `planRoute` doesn't differentiate;
  changing that is product work, not algorithm work).
- Performance beyond "interactive" (<150ms per route on a laptop for ≤5 zones).

## 4. Design decisions (pre-made)

1. **Algorithm: visibility graph over buffered zone vertices + Dijkstra.**
   - Inflate every configured zone (not just intersected ones) with
     `turf.buffer(zonePolygon, MARGIN_KM, { units: "kilometers" })`, `MARGIN_KM = 60`
     (≈0.5° — comfortably outside; tune in tests). Simplify the buffered ring to ≤64
     vertices (`turf.simplify`, tolerance 0.2) to bound graph size.
   - Nodes: origin, destination, and every vertex of every buffered ring.
   - Edge `(a,b)` exists iff the **great-circle** polyline between them
     (`greatCircleCoords(a, b, 32)`) does not intersect any **unbuffered** zone polygon
     (using the original zones keeps the margin as true clearance; buffered rings are only
     vertex generators).
   - Edge weight: `lengthKm` of that polyline. Run Dijkstra origin→destination; concatenate
     each hop's great-circle coords (dedupe joints) into the final `avoidancePath`.
   - Complexity: V ≤ ~70/zone × zones + 2; E checks are V² intersection tests — prune by
     skipping pairs whose straight bbox is > 1.5× the direct distance from the line, only if
     needed for the perf budget.
2. **Check against ALL zones, not just intersected ones.** Fixes the known
   detour-into-another-zone bug. `planRoute` keeps reporting `intersectedZones` from the
   *direct* path (UI contract), but the avoidance call now receives every zone.
3. **Fallback chain**: if Dijkstra finds no path (fully enclosed origin, pathological
   data), fall back to the existing single-waypoint heuristic; if that also fails, return
   `null` (UI already renders the "couldn't compute" message). Keep the old heuristic as a
   private function `singleWaypointFallback` rather than deleting it.
4. **High latitudes**: all distance/intersection math goes through turf great-circle
   functions, which are spherical — the only latitude-sensitive code today is the
   *degree-margin* logic being deleted. The buffered-km margin replaces it correctly.
5. **Antimeridian**: this is the fiddly one.
   - Detection: turf's `greatCircle` splits a ±180-crossing line into a MultiLineString;
     our `greatCircleCoords` flattens it, producing a bogus horizontal jump. For
     **drawing**, the UI tolerates it today (Leaflet draws a wrap line) — out of scope to
     fix rendering. For **intersection math**, the jump creates false positives/negatives.
   - Required behavior: routes whose direct path crosses ±180 **and** intersects no zone
     must keep working exactly as today (regression test: Tokyo→LA, zones=[Iran] →
     no intersection, `avoidancePath: null`).
   - For avoidance *near* the antimeridian (zone and route both crossing it): normalize by
     shifting longitudes into a continuous frame (`lng < 0 ? lng + 360 : lng`) for the
     graph computation when the direct path crosses ±180, then shift the result back.
     Add a test with a synthetic zone straddling ±180 (e.g. ring around the Bering Strait,
     route Anchorage→Petropavlovsk) — mark it `test.todo` if it proves out of reach, but
     the *no-false-positive* case (Tokyo→LA) is mandatory.
6. **Determinism**: no randomness anywhere — same inputs, same path (tests rely on it).

## 8. Edge cases & failure modes

- **Buffered polygons overlapping each other** (two zones close together): union them with
  `turf.union` before vertex extraction *only if* graph search fails without it — start
  simple.
- **Vertex exactly on a zone edge** after simplify: the buffer margin makes this
  practically impossible; if flaky tests appear, nudge MARGIN_KM, don't add epsilons.
- **Graph explosion** with future many-zone configs: cap total vertices at ~500 and fall
  back to the heuristic beyond it (log a console.warn).
- **`turf.buffer` returning undefined** for degenerate rings: guard and skip that zone
  with a warn (validation in P1.4 should prevent it upstream).
