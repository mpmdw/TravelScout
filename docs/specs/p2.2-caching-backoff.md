## 1. Mission

Centralize the ad-hoc caching that has grown inside individual providers into one tiny,
tested utility; add polite-citizen behavior for every external call — Nominatim usage-policy
compliance (1 req/s, real contact in the User-Agent), and exponential backoff with
`Retry-After` respect on `429`/`5xx` — so light production load neither violates free-API
policies nor falls over on transient errors.

## 2. Context — what exists today

- **Three cache implementations exist or will exist** by the time this runs:
  - `flights.ts:143-159` — `Map` + 5-min TTL, keyed `(lat2dp,lng2dp,date)`.
  - `amadeus.ts:11-35` — OAuth token cache (keep this one where it is; it's protocol
    state, not response caching).
  - `geoIntel.ts` (after P1.3) — per-region TTL cache with LRU cap and stale-serve.
- **Geocode** (`src/lib/geocode.ts`): every `/api/route` call fires **two** Nominatim
  requests (`route/route.ts:27-30`, `Promise.all`). Mitigations today: Next fetch
  `revalidate: 3600` (`geocode.ts:24`) — which only helps for *identical* URLs and only in
  prod build — and a **placeholder** User-Agent: `"TravelScout/0.1 (personal project;
  contact: set-your-email)"` (`geocode.ts:20`). Nominatim policy requires: max 1 req/s,
  a real contact address, no heavy use. The placeholder violates the spirit of it.
- **No backoff anywhere**: a 429 from Amadeus/Nominatim/AeroDataBox throws immediately and
  degrades to mock (good UX, but wasteful when one retry would have succeeded).
- All server runtime is Node (no edge runtime routes), so module-level state works, with
  the usual serverless caveat: on Vercel each lambda instance has its own memory — caching
  is best-effort, not correctness (that's fine for this app).

## 3. Non-goals

- No Redis/external cache (in-memory per-instance is the documented design point).
- No request coalescing/deduping beyond the cache (nice-to-have; skip).
- Do not touch the Amadeus OAuth token cache logic.
- No retry on POST-to-Claude (the Anthropic SDK already retries internally per P1.3).

## 4. Design decisions (pre-made)

1. **`src/lib/cache.ts`** — one class, no deps:
   ```ts
   export class TtlCache<V> {
     constructor(opts: { ttlMs: number; maxEntries?: number });  // maxEntries default 200, LRU-evict
     get(key: string): V | undefined;          // fresh only
     getStale(key: string): { value: V; ageMs: number } | undefined;  // ignores TTL
     set(key: string, value: V): void;
   }
   ```
2. **`src/lib/http.ts`** — `fetchWithBackoff(url, init, opts?)`:
   - retries on `429`, `502`, `503`, `504`, and network `TypeError`; **not** on other 4xx;
   - max 3 attempts; delays 500ms → 1500ms (+ full jitter), but honor a `Retry-After`
     response header (seconds or HTTP-date) when present and ≤ 10s, else give up;
   - per-attempt timeout via `AbortSignal.timeout(opts.timeoutMs ?? 10_000)`;
   - throws the final error with the attempt count in the message.
3. **`src/lib/http.ts` also hosts a `RateGate`** (for Nominatim's 1 req/s):
   a promise-chain serializer ensuring ≥`minIntervalMs` between *starts* of consecutive
   calls through the same gate. ~15 lines; used only by geocode for now.
4. **Geocode changes**:
   - cache: `TtlCache<Place|null>` keyed by `query.trim().toLowerCase()`, TTL 24h,
     maxEntries 500 — geocoding is stable; cache `null` results too (with the same TTL)
     to avoid re-hammering misses;
   - rate gate at 1100ms; calls go through `fetchWithBackoff`;
   - User-Agent: `TravelScout/0.1 (+contact: ${process.env.NOMINATIM_CONTACT || "unset"})`
     — and README instructs deployers to set `NOMINATIM_CONTACT` to an email/URL.
     Keep `Accept-Language: en` and drop the now-redundant `next: { revalidate }` hint.
5. **Provider refactors** (mechanical):
   - `flights.ts`: delete its local cache trio, use `TtlCache<FlightSearchResult>`
     (same key function, same 5-min TTL); route Amadeus REST calls (`amadeusGet`) through
     `fetchWithBackoff` (token POST too — it's idempotent).
   - `flightStatus.ts`/`aerodatabox.ts` (post-P1.2): add `TtlCache<FlightStatusResult>`
     keyed `(flightNumber,date)`, TTL 2 min (status is volatile); client fetch →
     `fetchWithBackoff`.
   - `geoIntel.ts` (post-P1.3): swap its bespoke Map for `TtlCache` using `getStale` for
     the serve-stale-on-error path. Behavior must stay identical to P1.3's contract.
6. **Cache only successes** everywhere (P1.3 precedent): error/fallback results are never
   `set()`.

## 8. Edge cases & failure modes

- **Fake-timer tests + promise chains**: RateGate tests need `await vi.advanceTimersByTimeAsync`.
- **`Retry-After: <http-date>` in the past** → treat as 0 delay.
- **Cache stampede** on cold start: acceptable (no coalescing per Non-goals) — the rate
  gate still serializes Nominatim, which is the only policy-sensitive endpoint.
- **Serverless memory churn**: TTL caches on Vercel may be empty per invocation — all
  consumers already treat the cache as optional; never *require* a hit.
- **Don't cache by raw user string without normalization** — key normalization rules are
  part of each decision above; keep them.
