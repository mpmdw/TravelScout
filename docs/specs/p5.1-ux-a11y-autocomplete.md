## 1. Mission

Take the UI from demo-grade to product-grade: every async card gets real loading/empty/
error states; the app is keyboard- and screen-reader-usable; the mobile layout works at
360px; and the origin/destination inputs get **location autocomplete** — using a
provider whose policy actually allows autocomplete.

## 2. Context — what exists today

`src/app/page.tsx` (515 lines, single client component) + `globals.css` (118 lines):

- **States**: route has loading+error (`:39-40`); flights and intel have loading but **no
  error state** — a failed fetch silently leaves the previous/empty content
  (`loadFlights:59-75` ignores `!res.ok`; `loadIntel:77-93` same). No empty-state
  distinction from not-yet-asked.
- **Forms**: inputs are not in a `<form>` — Enter doesn't submit; only the button works
  (`:158-166`). `<label>`s have no `htmlFor`/`id` association (`:141`, `:150`, `:476`,
  `:485`, `:495`). The status date input is a bare `type="date"`.
- **A11y**: no `aria-live` for async results; spinners are text divs (`.spin`); badge/
  heat colors carry meaning without text alternatives (they do have text content — OK);
  map div has `aria-label="Route map"` (`MapView.tsx:114`); color contrast unaudited
  (dark theme with `--muted` grays — audit needed); no skip link; no `:focus-visible`
  styling beyond inputs (`globals.css:69`, inputs only — buttons/links lack focus rings).
- **Mobile**: one breakpoint at 900px stacks map (46vh) over sidebar (`globals.css:50-53`).
  Unaudited below 400px; the topbar pill + tag likely overflow.
- **Autocomplete**: none. Geocoding is Nominatim server-side. **Nominatim's usage policy
  explicitly forbids autocomplete** — so the suggest endpoint must NOT call Nominatim.
- Layout has no `viewport`/`themeColor` exports (`layout.tsx` is bare; Next defaults
  cover viewport, but verify).

## 4. Design decisions (pre-made)

1. **Autocomplete provider: Photon** (`https://photon.komoot.io/api/?q=…&limit=5&lang=en`)
   — open, key-free, **built for autocomplete** (unlike Nominatim), returns GeoJSON with
   `name/city/country` properties and `[lng,lat]` coords. Proxy it server-side via a new
   `GET /api/geocode-suggest?q=…` route (keeps CSP `connect-src 'self'`, lets P2.2's
   `fetchWithBackoff` + a short `TtlCache` apply, and hides the provider choice).
   Fair-use: debounce 300ms client-side, min 3 chars, cancel in-flight via AbortController.
   On selection, the chosen suggestion's coords ride along; on free-text submit
   (no selection), the existing Nominatim `/api/route` path still resolves — **no behavior
   regression for typed-then-submitted text.** (If product later wants selected-coord
   passthrough into `/api/route`, that's an API change — out of scope; selection just
   fills the text field with an unambiguous string for now.)
2. **`PlaceInput` component** (new, client): label+input+listbox implementing the **ARIA
   combobox pattern**: `role="combobox"`, `aria-expanded`, `aria-controls`,
   `aria-activedescendant`; ↑/↓ to move, Enter to select, Esc to close; click-away closes;
   suggestions in a `role="listbox"` with `role="option"` children. No dependency — ~120
   lines. Used for both From and To.
3. **Async-state pattern**: one tiny discriminated union per card —
   `{ phase: "idle" | "loading" | "error" | "ready", … }` — replacing the boolean
   sprawl. Each card renders: idle hint (exists today), skeleton/spinner with
   `role="status"` + visually-hidden text, error block with a **Retry** button (calls the
   same loader), ready content. Flights/intel fetchers must set error state on `!res.ok`
   and on thrown fetch errors (fixing the silent-failure bug in Context).
4. **Forms**: wrap planner and status sections in `<form onSubmit>` (preventDefault →
   existing handlers); every label gets `htmlFor`; submit buttons get `type="submit"`;
   disable-while-loading stays.
5. **Live regions**: each results card gets `aria-live="polite"` on its content container
   so SR users hear updates (route summary, flights count, intel headline, status).
6. **Focus + contrast**: add a global `:focus-visible` outline (accent color, 2px) for
   buttons/links/options; bump `--muted` if contrast vs `--card` background is < 4.5:1
   (measure with a contrast tool; record before/after values in the PR).
7. **Mobile pass**: at ≤480px — topbar wraps (hide the `.tag`, keep the pill), sidebar
   padding tightens, font sizes hold ≥14px, map keeps ≥40vh, status date+flight inputs
   stack. Test at 360×740 in devtools; screenshot for the PR.
8. **`layout.tsx`**: add `export const viewport = { width: "device-width", initialScale: 1, themeColor: "#0b1220" }`.

## 8. Edge cases & failure modes

- **Suggestion races**: a stale response must never overwrite a newer query's list —
  AbortController + compare-latest-query guard.
- **Photon downtime**: endpoint returns `{suggestions: []}` — typed text still routes via
  Nominatim on submit. This is the G1 shadow-mode philosophy applied to UX.
- **`aria-activedescendant` + virtual focus** quirks in VoiceOver: test once; if hairy,
  fall back to roving `tabIndex` — pattern choice is the agent's call, accessibility of
  the *outcome* is the requirement.
- **Date input on mobile Safari**: native picker is fine; just ensure the label
  association so it's announced.
- **Layout shift from skeletons**: size skeleton blocks to typical content heights to
  avoid CLS jank.
