## 1. Mission

Stand up Vitest with a small, meaningful suite: a **regression test for the fixed
signed-shift bug** in the flight-status mock (`>>` → `>>>`), avoidance-correctness tests
that pin current routing behavior, and unit tests for the pure helpers — wired into
`npm test` and the CI workflow.

## 2. Context — what exists today

- **Zero tests, zero test deps, no `test` script** (`package.json:6-11`).
- CI (`.github/workflows/ci.yml`) runs `npm ci && npm run build` on Node 22; its header
  comment says *"Add lint + tests here as part of roadmap P2.4"* — tests are this task;
  **lint stays with P4.2**.
- TS path alias `@/*` → `src/*` is used by app code (check `tsconfig.json` — vitest needs
  the same alias configured).
- **The signed-shift bug story** (the roadmap-mandated regression test): in
  `src/lib/providers/flightStatus.ts`, `hashStr` (`:53-57`) accumulates with `>>> 0` so
  `h` is an unsigned 32-bit int that can exceed 2³¹. Downstream, `depMin = (h >>> 3) % 60`
  (`:81`) uses an **unsigned** shift — the comment "unsigned shift: h can exceed 2^31"
  marks where a signed `>>` once produced a *negative* `depMin`, which produced an invalid
  `Date` and `"Invalid Date".toISOString()` throws / NaN times. The fix is already in;
  the test must pin it forever: find inputs where `h ≥ 2³¹` and assert sane output.
  Note `(h >>> 4)` and `(h >>> 6)` at `:105,:112` have the same property.
- Pure, exported, easily testable surfaces:
  - `getFlightStatus` / mock determinism (`flightStatus.ts`) — async, no network without key.
  - `planRoute`, `greatCircleCoords` (`geo.ts`) — pure geometry, no I/O.
  - `DANGER_ZONES` (`dangerZones.ts`) — data sanity.
  - NOT exported (don't test yet): `extractJson` in geoIntel (P1.3 exports it — add the
    test then/if merged), `isoDurationToMin` in flights.ts (private; skip or test via
    public behavior).
- Things that need mocking if touched: `fetch` (geocode, amadeus), Anthropic SDK — **out
  of scope**; this task tests only key-free pure paths (G1 means they're substantial).

## 4. Design decisions (pre-made)

1. **Vitest** (roadmap-specified), node environment, globals on:
   ```ts
   // vitest.config.ts
   import { defineConfig } from "vitest/config";
   import path from "node:path";
   export default defineConfig({
     test: { environment: "node", globals: true, include: ["tests/**/*.test.ts"] },
     resolve: { alias: { "@": path.resolve(__dirname, "src") } },
   });
   ```
2. **Dev deps**: `vitest` only (no jsdom — node env suffices; no UI tests here).
3. **Scripts**: `"test": "vitest run"`, `"test:watch": "vitest"`.
4. **Layout**: flat `tests/<area>.test.ts` (the roadmap names a `tests/` dir):
   `tests/flightStatus.test.ts`, `tests/avoidance.test.ts`, `tests/geo.test.ts`,
   `tests/dangerZones.test.ts`.
5. **Determinism over snapshotting**: assert properties (ranges, invariants, ISO-parses)
   rather than exact geometry snapshots, so P1.4/P2.3 don't churn this suite.
   Exception: pin `intersectedZones` ids for known crossing pairs — that's the product
   contract.
6. **CI**: insert `- run: npm test` between `npm ci` and `npm run build` in `ci.yml`, and
   update the header comment (lint remains reserved for P4.2).

**Step 2 — `tests/flightStatus.test.ts`.**
- *Regression (signed shift)*: brute-force a handful of keys whose `hashStr(key+date) ≥ 2**31`
  (re-implement `hashStr` inline in the test — 5 lines — or export it; **exporting is
  better**: do that). For each: `getFlightStatus({ flightNumber, date })` resolves; every

- *Date handling*: `date: "2026-02-31"`-style garbage → still resolves without throwing

## 8. Edge cases & failure modes

- **Finding h ≥ 2³¹ inputs**: don't hardcode magic strings without checking — compute in
  the test (`for` over candidate keys until `hashStr(...) >= 2**31`, assert you found ≥3).
  This keeps the test true even if `hashStr` changes.
- **turf import cost**: `@turf/turf` is heavy; fine in tests, but keep imports specific if
  suite startup exceeds ~5s.
- **Timezone flake**: never assert local-time renderings; ISO strings only.
- **`mockStatus` uses `Date.now()`** when the date regex fails — that's why Step 2 pins
  no-throw rather than values for garbage dates.
