## 1. Mission

Make production failures visible: a `/api/health` endpoint suitable for uptime checks, a
tiny structured (JSON-line) logger replacing stray `console.error`s, and centralized error
capture (Sentry) that — like every other integration in this app — is a no-op until its
key exists.

## 2. Context — what exists today

- **No health endpoint, no logger, no error tracking.** After P2.1, every API route has a
  try/catch emitting `console.error(e)` + a 500 envelope — those are the capture points.
- Failure modes worth observing (from earlier phases): provider fallbacks to mock
  (currently invisible — a dead Amadeus key just looks like mock mode), Nominatim 403s,
  geo-intel timeouts racing the platform limit (p4.1 §8), login throttling events (P3.1).
- `getConfig()` exposes which features have keys — health can report feature flags
  without leaking values (`hasClaude()`, `hasFlightSearch()`, `hasFlightStatus()` from
  `src/lib/config.ts`).
- Next 15 instrumentation surfaces: `src/instrumentation.ts` (`register()`, `onRequestError`)
  — the sanctioned hook for request-error capture in App Router; `@sentry/nextjs` wires
  itself through it.
- P3.2's CSP has a comment marking where Sentry's ingest host must be added to
  `connect-src` **only if** client-side Sentry is enabled (decision below: server-only,
  so no CSP change needed — keep the comment for the future).
- Vercel provides function logs natively — structured JSON lines make them searchable.

## 3. Non-goals

- No metrics/tracing stack (OTel, Prometheus) — log lines + Sentry is the right size.
- No client-side (browser) Sentry — server-only capture keeps the CSP untouched and the
  bundle lean; the UI already surfaces errors to users via envelopes.
- No log persistence beyond the platform's (Vercel) retention.
- No alerting rules (Sentry's defaults + Vercel's emails suffice at this scale).

## 4. Design decisions (pre-made)

1. **`/api/health`** returns 200 always (it reports state; an uptime checker alerts on
   non-200 only for true outages):
   ```json
   {
     "ok": true,
     "version": "<package.json version>",
     "uptimeSec": 123,
     "features": { "claude": false, "flightSearch": true, "flightStatus": false,
                    "authGate": true, "errorTracking": false },
     "time": "2026-06-09T…Z"
   }
   ```
   Feature booleans come from the `has*()` flags — **names of capabilities, never values
   or fragments of keys** (G2). `dynamic = "force-dynamic"`. The auth middleware must
   exempt `/api/health` (add to P3.1's `PUBLIC_PATHS`) so uptime checkers don't need
   credentials — it leaks only booleans, acceptable; state this in the code comment.
2. **`src/lib/log.ts`** — ~40 lines, zero deps:
   ```ts
   type Level = "debug" | "info" | "warn" | "error";
   export const log: Record<Level, (msg: string, fields?: Record<string, unknown>) => void>;
   ```
   Emits one JSON line to stdout/stderr: `{ level, msg, time, ...fields }`. `LOG_LEVEL`
   filters (default info). Fields must already be serializable — no magic. Errors pass
   `{ err: e instanceof Error ? { message, stack } : String(e) }`.
3. **Adoption sweep**: replace `console.error` in route catches with
   `log.error("route_failed", { route: "/api/flights", err })`; add `log.warn` at every
   **fallback-to-mock** site in providers (`flights.ts`, `flightStatus.ts`,
   `geoIntel.ts`) — this is the single highest-value observability change in the task:
   silent mock degradation becomes a searchable `provider_fallback` event.
4. **Sentry, server-only**: `npm i @sentry/nextjs`; hand-write the minimal config (skip
   the wizard — it scaffolds client + edge configs we don't want):
   - `src/instrumentation.ts`: `register()` initializes Sentry **iff `SENTRY_DSN` is
     set** (`tracesSampleRate: 0` — errors only); export `onRequestError` delegating to
     `Sentry.captureRequestError` (guarded by the same flag).
   - `log.error` additionally forwards to `Sentry.captureException` when initialized —
     one call site captures both signals.
   - No `sentry.client.config.ts`, no source-map upload step (server stacks are readable
     enough unminified on Vercel; revisit if not).
5. **Config**: add `sentryDsn`, `logLevel` to `getConfig()`; `hasErrorTracking()` flag.
   Document both env vars twice (G3).

## 8. Edge cases & failure modes

- **`uptimeSec` on serverless** is instance uptime, not service uptime — name it
  `instanceUptimeSec` to avoid misreading dashboards.
- **Logging inside the logger**: never throw from `log.*` (wrap serialization in
  try/catch; fall back to `console.error("log_serialize_failed")`).
- **PII/secret discipline in fields**: log region names and IATA codes freely; never log
  full request bodies, cookie values, or Authorization headers. Add this as a comment at
  the top of `log.ts`.
- **Sentry tree-shaking**: with no DSN, `@sentry/nextjs` still adds server cold-start
  weight; if measured cold-start regresses noticeably on Vercel, lazy-`import()` Sentry
  inside `register()` — note this in code.
- **Health-check abuse**: it's public and cheap (no I/O); rate limiting it is unnecessary.
