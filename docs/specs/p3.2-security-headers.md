## 1. Mission

Ship a Content-Security-Policy and the standard security-header set on every response, and
**prove** (with a scripted check, not vibes) that no API key or secret reaches the client
bundle.

## 2. Context — what exists today

- `next.config.mjs` is 6 lines: `reactStrictMode: true` only. **No headers configured
  anywhere**; middleware adds none.
- Client-side reality that constrains the CSP:
  - **Leaflet + OSM tiles**: `MapView.tsx:31` loads raster tiles from
    `https://{s}.tile.openstreetmap.org/...` → `img-src` needs
    `https://*.tile.openstreetmap.org`. Leaflet also builds some UI from CSS in
    `leaflet/dist/leaflet.css` (bundled by Next — served same-origin) and uses inline
    `style=""` attributes on panes/markers → style CSP must allow inline styles.
  - **React inline style props** are used throughout `page.tsx` (e.g. `:232`, `:284`) —
    these are `style` attributes, governed by `style-src-attr`/`style-src 'unsafe-inline'`.
  - **No external scripts, no external fonts, no analytics** today. `globals.css` is
    bundled. No `<Script>` tags, no Google Fonts (layout.tsx is bare).
  - **Next.js dev mode** needs `'unsafe-eval'` (react-refresh) and inline scripts; prod
    App Router still emits **inline bootstrap scripts** → `script-src` needs
    `'unsafe-inline'` unless you do nonces. (Decision below: skip nonces.)
  - Client fetches are all same-origin `/api/*` (`page.tsx`) → `connect-src 'self'`
    (+ `ws:` in dev for HMR).
- Secrets currently server-side only by construction: `getConfig()`/`process.env` reads
  live in `src/lib/**` and middleware; nothing client-side imports them
  (`page.tsx`/`MapView.tsx` import only types). No `NEXT_PUBLIC_*` vars exist. This task
  adds the *automated proof*.
- After P3.1 there is a login page + cookie; HSTS interacts with tunnels (trycloudflare
  is HTTPS — fine).

## 3. Non-goals

- No nonce-based strict CSP (Next App Router + static pages makes this a project of its
  own; the win over `'unsafe-inline'` for this app's threat model doesn't justify it —
  there is no user-generated HTML rendered anywhere).
- No CORS configuration (none exists; adding permissive CORS would be a regression).
- No cookie work (P3.1 owns cookies), no rate limiting.
- No subresource integrity (no third-party scripts exist).

## 4. Design decisions (pre-made)

1. **Headers via `next.config.mjs` `headers()`** (static, cacheable, applies to pages and
   API routes), not middleware. Middleware-set headers are easy to accidentally drop on
   early returns (e.g. P3.1's 302/401 paths) — accept that those middleware short-circuit
   responses carry no CSP (they render no HTML).
2. **The header set** (apply to `source: "/(.*)"`):

   | Header | Value |
   |---|---|
   | `Content-Security-Policy` | see below |
   | `X-Content-Type-Options` | `nosniff` |
   | `Referrer-Policy` | `strict-origin-when-cross-origin` |
   | `X-Frame-Options` | `DENY` (belt) — CSP `frame-ancestors 'none'` (suspenders) |
   | `Permissions-Policy` | `camera=(), microphone=(), geolocation=(), payment=()` |
   | `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` (Vercel also sets one; identical value avoids conflict) |
   | `X-DNS-Prefetch-Control` | `off` |

3. **CSP** (single line in code; shown wrapped here):
   ```
   default-src 'self';
   script-src 'self' 'unsafe-inline' 'unsafe-eval';   ← dev only gets unsafe-eval (see 4)
   style-src 'self' 'unsafe-inline';
   img-src 'self' data: blob: https://*.tile.openstreetmap.org;
   connect-src 'self' ws: wss:;                        ← ws only in dev (see 4)
   font-src 'self';
   object-src 'none';
   base-uri 'self';
   form-action 'self';
   frame-ancestors 'none';
   upgrade-insecure-requests                           ← prod only
   ```
4. **Dev/prod split**: build the CSP string in the config from
   `process.env.NODE_ENV === "development"` — dev adds `'unsafe-eval'` and `ws: wss:`;
   prod omits them and adds `upgrade-insecure-requests`. Keep one source of truth (a
   small `csp(isDev)` function in the config file).
5. **Secret-hygiene proof** — a script, committed as `scripts/check-client-secrets.sh`,
   run manually here and adopted by CI in P4.2:
   ```bash
   #!/usr/bin/env bash
   set -euo pipefail
   npm run build >/dev/null
   # Names of every secret-bearing env var (keep in sync with .env.example):
   PATTERN='ANTHROPIC_API_KEY|AMADEUS_CLIENT_SECRET|AMADEUS_CLIENT_ID|FLIGHT_STATUS_API_KEY|BASIC_AUTH_PASS|AUTH_SECRET|AUTH_PASS_HASH'
   if grep -rE "$PATTERN" .next/static 2>/dev/null; then
     echo "FAIL: secret-bearing env var name found in client bundle"; exit 1
   fi
   echo "OK: no secret env names in client bundles"
   ```
   (Checking for *names* catches inlined `process.env.X` references — Next inlines the
   value and drops the name only for `NEXT_PUBLIC_*`; a bare name appearing in static
   chunks means someone imported server config client-side.)
6. **Documented manual check** in README (security section, 3 lines): how to re-run the
   script and how to view headers (`curl -sI`).

## 8. Edge cases & failure modes

- **Leaflet marker icons**: we use `circleMarker` (SVG, no external images), but if P5.2
  later adds default Leaflet markers they load from the bundle (`'self'`) — already
  covered; note it for P5.2.
- **`data:`/`blob:` in img-src**: Leaflet uses data-URI cursors/shadows in some builds —
  keep both allowances.
- **Vercel duplicate HSTS**: duplicate identical headers are legal; if Vercel's differs,
  prefer removing ours in P4.1 rather than fighting the platform.
- **`upgrade-insecure-requests` on plain-http LAN demos**: it upgrades subresources only;
  the OSM tiles are already https. No action.
- **Future third-party additions** (Sentry in P4.3!): Sentry's browser SDK needs
  `connect-src` for its ingest URL — leave a comment in `csp()` pointing P4.3 at the
  right line.
